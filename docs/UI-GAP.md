# 与参考实现的界面差异

参照来源：**iPhone 上的 SenPlayer 实机截图**（2026-10-12，滚动截图在
`_re/ui-shots/iphone-2026-10-12/`，播放器关键帧在 `_re/ui-shots/iphone-player/`，
两者都在仓库之外）。Mac 版是原生 macOS 程序（`CFBundleSupportedPlatforms = MacOSX`），
左栏布局不可直接照搬，因此以真机 iOS 版为准。

## 一、一级导航的组织不同

| | 参考 | 本仓 |
|---|---|---|
| 一级入口 | 首页 / 媒体库 / 记录 / 搜索 / 设置 | 媒体库 / 服务器 / IPTV / 记录 / 设置 |

参考**没有**独立的「服务器」和「IPTV」一级入口——服务器列表就在「媒体库」里（该页标题是
「资源」），IPTV 只是这一页里的一个分组；反过来「搜索」是独立的一级入口。

## 二、首页

参考首页分三段：顶部整幅海报轮播（带剧名）→「继续观看」横排海报卡 →「我的媒体」横排海报卡；
右上角还有 TV/手机切换与头像。
本仓首页是「URL 列表」和「本地文件」两段提示文字。

## 三、资源页（即参考的「媒体库」）

参考：标题「资源」→ 搜索框 → 右上 `+` / 排序 / 更多 → 分组标题（本地文件、相册视频、
网络连接、IPTV）→ **两列卡片**，每张带彩色图标、名称、端口信息（如「IP 216 : 13481 主线路」）、
最后访问时间（「1月前」）。进入服务器后是影视海报墙（三列），带分类标签（Remux / 动作片 /
4K 蓝光 / 华语电影 / 外语电影 / 日韩电影）。

本仓：单列列表行，没有图标、分组、搜索框或工具栏。

## 四、影片详情页

参考自上而下：整幅剧照 → 剧名 → 元数据行（`54:59 min · 2022年2月8日 · 4K HDR10 ·
23.976 FPS · 5.5Gb`）→ 大圆角「播放」按钮 → 标签行（HDR10 / 5.1 / 字幕…）与收藏
→ 季/集选择器加分集缩略图行 → 媒体信息表（容器 mkv、视频 H.265 1920×804、音频 5.1、
字幕 2 轨，含完整参数）→ 演员人员横排头像 → 类似作品横排海报。

## 五、播放器（差异最大的一处）

- 顶部第一行：OSD（时间 + FPS + 网速）在左，**影片标题居中**，电量与充电状态在右。
- 顶部第二行：左起 `关闭` `投屏` `倍速` `旋转`，右起 `画中画` `字幕` `截图` `弹幕`。
- 媒体信息行：`HW HEVC HDR 2160p 23FPS 14.1mbps`（硬解、编码、HDR、分辨率、帧率、码率）。
- 进度条行：左侧当前时间，中间细条加圆滑块，右侧总时长。
- 底部一行：左 `锁定`，中 `上一个 / 暂停 / 下一个`，右 `播放列表`。
- 字幕菜单（点字幕图标弹出）：`主字幕 [30/32]`（副标题显示当前轨道）→ `副字幕 [0/31]` →
  `字幕搜索` → `本地导入` → `字幕设置` → `字幕遮挡` → `永久禁用`。
  **主副字幕是两条独立轨道。**
- 「更多」菜单：`硬解码` / `顺序播放` / `片头片尾` / `更多`，每项带二级箭头。
- 长按画面出现「倍速播放 2.0X」提示。
- 字幕渲染是纯文字带描边，**没有背景色块**。

## 六、此前判断错的三处

| 键 | 当时的判断 | 实机证据 |
|---|---|---|
| `kShowPlayerListButton` | 「本仓没有对应控件」 | 播放器底部右侧就是一个播放列表按钮 |
| `kShowPlayerDlnaButton` | 「iOS 走系统 AirPlay 按钮，不在控制栏」 | 顶部左侧画了独立的投屏按钮 |
| `kShowOSDInternetSpeed` | 「Android 侧没有字节计数，落不下去」 | OSD 里网速与时间、FPS 并列常驻 |

三条都是「grep 不到就当作不存在」的同一个错误。判断一个控件该不该有，依据应是
**实机界面**，而不是本仓现有的代码里有没有它的位置。

## 七、建议的动手顺序

1. 一级导航 + 首页（决定其余页面往哪放，现在改成本最低）
2. 资源页卡片化（图标、分组、搜索框、工具栏）
3. 播放器控制栏按第五节的六行结构重排，并补媒体信息行与主副字幕
4. 详情页按第四节补齐

## 八、设置页的真实结构（来自 5 分 42 秒实机录屏）

录屏抽帧在 `_re/ui-shots/iphone-recording/`（2026-10-12 16:10 录制，342 秒）。

设置首页是**分组卡片**，不是 iOS 标准列表：

- **媒体库配置**：选择 Trakt / 播放设置 / 界面偏好 / 播放手势 / 媒体控制
- **视频设置** / **音频设置** / **字幕设置** / **弹幕设置**
- **给个好评** / **缓存管理** / **关于我们**
- 顶部一行显示「SenPlayer Pro（已解锁）」以及更新与关于入口

「列表配置」页十余项：显示播放进度、显示文件名称、名称过长时省略、显示文件夹、SMB3、
显示隐藏的 SMB 共享、演出电影信息、文件时长、文件大小、**New 标记**、HDR 标记、帧率、
分辨率、分辨率简化显示。

「视频设置」页：**智能解码模式（硬解码 HWVPU）**、软件解码线程、**杜比 7 转 P8.1**、
**HDR Vivid**、缩放模式、JPEG 图像质量、自动抖动预览，末尾两行适用范围说明。

双击屏幕截图、双击屏幕锁定。

## 九、又纠正五处判断

| 键 | 当时的判断 | 实机上 |
|---|---|---|
| `kEnableDolbyP7ToP81` | 「iOS 的 Profile 转换属于系统，应用没有开关」 | 「视频设置」里就叫**杜比 7 转 P8.1**，是应用自己的开关 |
| `kVideoUpscalingLevel` | 「Media3 没有对应接口，单端不做」 | 「视频设置」里有**缩放模式** |
| `list.showNewTag` | 「找不到依据，暂不实现」 | 「列表配置」里就是 **New 标记** |
| `kSubtitleHDRBrightnessValue` | 「Media3 没有对应接口」 | 「字幕设置」里的 **HDR 字幕** |
| `kSubtitleAutoadapt` | 未列 | 「字幕设置」里的 **字幕适配** |

连同第七节的三条，这八条有一个共同点：**在既有取证材料里找不到就直接判定它不存在**,
而实机截图和录屏一直都是拿得到的。判断一个功能该不该有，依据必须是那个 app 本身。

## 十、详情页本来就没有缺项（第四次同款误判）

第七节列的「详情页补齐（媒体信息表 / 演员 / 类似作品）」不成立 —— 两端都不成立。

iOS 的 `DetailScreen.swift` 早就具备：海报（`AsyncImage` 拉 `imageURL`，是真图不是占位）、
评分（★ 8.5，受 `showRating` 控制）、facts 一行（年份 · 时长 · HDR · 分辨率）、
播放按钮（按 `positionMs` 决定写「播放」还是「继续播放」）、简介（`overview`）、
演职人员（`cast`）、类似作品（`similarSection`）。

Android 的 `DetailScreen.kt` 同样：`AsyncImage` 海报、`overview`（125 行）、
`cast`（134 行）、`similar`（137–155 行，走 `client.similar()`）。

数据来源也早就在 `Servers.swift` 里：请求的 `Fields` 已经带
`Overview,People,Genres,Studios,Tags`，346 行解析 People、395 行解析 Overview，
272 行还有 Emby 自己的相似度接口。

这是第四次「先判定该做、查完发现已有」。连同第九节那五条，共同点始终是同一个：
**从参照实现的截图倒推我们缺什么，而不是先读自己的代码。**
